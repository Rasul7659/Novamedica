# Novamedica: сайт клиники и админка (Node.js)

> Ветка **`node`**: серверная часть на Node.js (Express). Нужен сервер с Node.js и постоянным диском. Версия для обычного виртуального хостинга лежит в ветке `php`, полная сборка с обоими вариантами в `main`.

Адаптивный лендинг клиники и админ-панель по адресу **`/admin`**. Правки в админке сначала сохраняются как черновик и попадают на сайт только после кнопки «Опубликовать».

## Требования

Node.js ≥ 18, постоянный диск под папку данных. База данных не нужна: данные хранятся в JSON-файлах. Подходят VPS, Render, Railway, Fly.io, Docker.

## Структура

```
server/       Express: API, вход, рендер лендинга, хранилище
public/       CSS, JS и картинки лендинга
admin/        интерфейс админки (vanilla JS, без сборки)
app.js        точка входа для хостингов с Passenger
Dockerfile    образ (данные в /data)
.env.example  переменные окружения
test/api.test.js   23 сквозные проверки по HTTP
```

## Что умеет админка

| Раздел | Что делает |
|---|---|
| Главная | новые заявки, число неопубликованных изменений, что осталось заполнить |
| Заявки | статусы (новая → ждём ответа → записан / отказ), заметки, звонок и WhatsApp в один клик, уведомления в Telegram |
| Тексты и контакты | заголовки, телефон, адрес, реквизиты, **номер лицензии**, предпросмотр блока |
| Услуги и цены | добавить, изменить, скрыть (удалять нельзя, только скрывать) |
| Врачи | карточки с фото, специальность (работает фильтр на сайте), стаж, скрытие |
| Фото и видео | загрузка (сжатие, удаление EXIF), выбор мест на сайте, замена, удаление неиспользуемых |
| Публикация и история | список изменений, «Не публиковать», предпросмотр `/preview`, откат к прошлой версии |

Без номера лицензии публиковать нельзя.

## Запуск

```bash
npm install
cp .env.example .env     # по желанию; можно задать переменные в панели хостинга
npm start                # http://localhost:3000, админка: /admin
npm test                 # сквозные проверки
```
При первом запуске создаётся администратор (`ADMIN_EMAIL`, по умолчанию `admin@novamedica.ru`, и `ADMIN_PASSWORD`). Если пароль не задан, он генерируется и один раз показывается в консоли.

## Развёртывание

1. Задайте переменные окружения (все описаны в `.env.example`): `ADMIN_PASSWORD`, `PUBLIC_URL`, при необходимости `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SMTP_*`.
2. `DATA_DIR` должен указывать на постоянный диск: там контент, заявки, фото и хеш пароля. **Делайте резервные копии этой папки.**
3. За прокси или балансировщиком включите `TRUST_PROXY=true`, в боевом режиме `NODE_ENV=production` (cookie получает флаг Secure, нужен HTTPS).
4. Docker: `docker build -t novamedica .`, затем `docker run -p 3000:3000 -v novamedica-data:/data -e ADMIN_PASSWORD=… novamedica`.

## Безопасность

- Пароль хранится в хеше (scrypt); 5 неверных попыток блокируют вход на 15 минут.
- Сессия — подписанный HttpOnly-cookie (`SameSite=Lax`): 12 часов или 30 дней при «Запомнить меня». Смена пароля завершает все сессии.
- Изменяющие запросы админки требуют заголовок `X-Requested-With` (защита от CSRF).
- Загрузки проверяются по содержимому файла, фото пересжимаются (sharp), метаданные (в том числе GPS) удаляются.
- Весь пользовательский текст экранируется при выводе, действует строгая CSP.
- Форма заявки: ограничение частоты, скрытое поле-ловушка для ботов, обязательное согласие на обработку данных.

## Что осталось на стороне клиники

Номер лицензии, телефон, адрес, реквизиты, цены, фамилии и фото врачей, фото интерьера (сейчас везде визуализация), тексты политики конфиденциальности и согласия на обработку данных (ссылки в подвале пока ведут вниз страницы).
