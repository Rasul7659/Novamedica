# Novamedica: сайт и админка

Адаптивный лендинг клиники и админ-панель для сотрудников. Лендинг собирается сервером из опубликованного содержимого, админка находится по адресу **`/admin`**.

## Запуск

```bash
npm install
cp .env.example .env      # по желанию; можно задать переменные в панели хостинга
npm start                 # http://localhost:3000
```

При первом запуске создаётся администратор (`ADMIN_EMAIL`, `ADMIN_PASSWORD`). Если пароль не задан, он генерируется и один раз печатается в консоль. Вход: `http://localhost:3000/admin`.

Проверки: `npm test`.

## Что умеет админка

| Раздел | Что делает |
|---|---|
| Главная | новые заявки, число неопубликованных изменений, что осталось заполнить |
| Заявки | статусы (новая → ждём ответа → записан / отказ), заметки, звонок и WhatsApp в один клик, уведомления в Telegram |
| Тексты и контакты | заголовки, телефон, адрес, реквизиты, **номер лицензии**, предпросмотр блока |
| Услуги и цены | добавить, изменить, скрыть (удалять нельзя, только скрывать) |
| Врачи | карточки с фото, специальность (работает фильтр на сайте), стаж, скрытие |
| Фото и видео | загрузка (сжатие, удаление EXIF), выбор мест на сайте, замена, удаление неиспользуемых |
| Публикация и история | список изменений, «Не публиковать», предпросмотр, откат к прошлой версии |

Главное правило: **«Сохранить» не меняет сайт**. Правки видны только в админке (и в предпросмотре `/preview`), пока не нажата «Опубликовать». Без номера лицензии публиковать нельзя.

## Структура

```
server/      Express: API, вход, рендер лендинга, хранилище
public/      CSS, JS и картинки лендинга
admin/       интерфейс админки (vanilla JS, без сборки)
test/        сквозные тесты API
data/        данные (создаётся сама, в git не попадает)
```

Данные лежат в `DATA_DIR`: `content.json` (черновик, опубликованное, история), `requests.json` (заявки), `admin.json` (хеш пароля), `uploads/` (фото). **Делайте резервные копии этой папки.**

## Развёртывание

Нужен хостинг с Node.js ≥ 18 и **постоянным диском** под `DATA_DIR`: VPS, Render, Railway, Fly.io и подобные. GitHub Pages не подойдёт: он отдаёт только статические файлы, а админке нужен сервер. Есть `Dockerfile` (данные в `/data`).

Для боевого запуска:
1. Задайте `ADMIN_PASSWORD` (или возьмите пароль из консоли при первом старте).
2. Включите HTTPS (cookie входа получает флаг `Secure` при `NODE_ENV=production`) и `TRUST_PROXY=true` за прокси.
3. Укажите `PUBLIC_URL`, чтобы ссылки в письмах вели на ваш домен.
4. По желанию подключите Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) и SMTP.

## Безопасность

- Пароль хранится в виде scrypt-хеша; блокировка на 15 минут после 5 неудачных попыток входа.
- Сессия: подписанный HttpOnly cookie (`SameSite=Lax`), 12 часов или 30 дней при «Запомнить меня». Смена пароля завершает все сессии.
- Изменяющие запросы админки требуют заголовок `X-Requested-With` (защита от CSRF).
- Загрузки проверяются по содержимому файла, фото пересжимаются, метаданные (в том числе GPS) удаляются.
- Весь пользовательский текст экранируется при выводе, действует строгая CSP.
- Форма заявки: ограничение частоты, скрытое поле-ловушка для ботов, обязательное согласие на обработку данных.

## Что осталось на стороне клиники

Номера лицензии, телефон, адрес, реквизиты, цены, фамилии и фото врачей, фото интерьера (сейчас везде визуализация), тексты политики конфиденциальности и согласия на обработку данных (ссылки в подвале пока ведут вниз страницы).
